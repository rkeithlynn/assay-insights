# scripts

Operational scripts, run with `uv run` from the repository root. Each reads the AWS
profile, Region and resource names from the Pulumi stack's config and outputs.

| Script | Does |
| --- | --- |
| `migrate.py` | Runs the migration Lambda: database roles, `alembic upgrade head`, and the RLS and role checks. `--command verify` is read-only. Run it after every `pulumi up` that changes `db/`. |
| `add_tenant.py` | Adds a business tenant and waits for provisioning: `--name`, `--admin-name`, `--admin-email`. Prints the tenant ID. `--retry <tenant id>` retries a failed tenant. |
| `run_isolation.py` | Runs `tests/isolation` inside the VPC against two tenants, then the provisioning role's probe and the worker task's probe, and prints each result. It also checks the portal app clients against Cognito and prints the refresh-token rotation probe (what Cognito stores and allows for a client with rotation on; for the owner's decision, not pass or fail). See `tests/isolation/README.md`. |
| `update_tenants.py` | Runs every active tenant's stack again (the provisioning task's `update` command), so a change to the tenant stack program reaches existing tenants: build step 6's bucket CORS and inbox-only malware scanning. `--tenant <id>` (repeatable) limits it. Changes AWS resources, as `pulumi up` does: the owner runs it, after `pulumi up`. |
| `make_test_files.py` | Writes synthetic browser-check files to `.test-files/` (git-ignored): a plain PDF, the same PDF under another name (duplicate), a password-protected PDF (40-bit RC4) and a second with a 128-bit key (`07-password-protected-128.pdf`), a PDF with a valid companion file and one with an invalid one (four key errors, all reported at once), and plain text named `06-not-a-pdf.pdf`. `--tenant-id` puts that tenant's ID in the valid companion. `--fresh` adds a new run ID to every page of every PDF, so none stops as a duplicate of an earlier upload (within one run, 02 is still 01). Never the EICAR file (see CLAUDE.md, build step 6). |
| `ingest_check.py` | Exercises the pipeline in AWS through the portal's own API, signed in with your portal tab's access token (hidden prompt; never echoed, logged or stored). `bad-companion`: a PDF and a companion file with six errors; close must be refused. `eicar`: the EICAR test file, assembled in memory from a masked form, registered as a PDF; it must be quarantined, and its view link refused. Prints the tenant and asks before creating anything; refuses any tenant but `--tenant`. Standard library only, Python 3.9+, so it also runs in AWS CloudShell. |
| `seed.py` | Seeds the environment from stack config: verifies each `aiModels` profile with a test call, loads the catalog, creates the platform tenant and its users, adds the business tenants through the portal's add-tenant path and waits for them, invites their users and gives every tenant its default models. Safe to run again. |
| `check_deployment.py` | Read-only checks of a deployed stack. Warns if the account's Lambda concurrent-executions limit is below what the pipeline needs (1,000; a new account allows 10). Fails if a configured log destination has received nothing: for every resource with the stack's tags it reads where the logs are configured to go and whether anything has arrived. A log that is empty because its source was never active (the break-glass log) is reported as not proven, and fails only with `--strict`. `--before-deploy` runs the concurrency check alone, for a new account. Run it after the isolation run, which starts every task. |
| `export_openapi.py` | Writes `portal/src/api/openapi.json` from the API; then `npm run gen:api` in `portal/`. `--check` fails if it is out of date. |
| `build_image.py` | Builds and pushes a container image. Run by Pulumi during `pulumi up`, not by hand. |
| `build_portal.py` | Builds the portal in its container and uploads it. Run by Pulumi during `pulumi up`, not by hand. |
